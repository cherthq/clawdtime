# Native control repair

Prepared November 12, 2026. Companion 0.2.1, build 3. Source and internal artifact
hashes are recorded in the local release manifest. Installation is not yet approved.

The 0.2.0 helper treated old submitted inputs as unresolved because the previous
helper never recorded its new observation marker. A fresh coding chat cannot fix
this device-wide migration issue. Separately, initial connector registration must
describe the native tools actually available in the originating chat; a run
registered with no native capability cannot acquire it during a call.

The repair keeps the original receipt journal and adds a separate, audited record
of closed historical ownership. It distinguishes backend-observed history from
history whose application outcome remains unverified. Pending and unknown input
remain blocking. Exact snapshot/receipt bindings, closed ownership evidence,
fresh operator attestations and the helper's exclusive journal lock are required.
Retired leases cannot be used again. The source skill checks native capability
before calling, then uses the same chat's normal tools directly after acquiring
exclusive ownership. No replacement agent is involved.

## Prepared evidence

All 41 pre-upgrade submissions have retained closure evidence. Thirty-seven match
backend observed actions with post-action frame metadata. Four match stopped,
expired gateway leases and ended calls in the prior ClawdTime handoff audit;
their observation remains unavailable. Neither category asserts application
success. A protected isolated-copy rehearsal passed dry-run, apply and helper
journal reopening: zero remaining blockers, 37 historically observed, four
historically unverified. Original copied journal bytes and live journal bytes
were unchanged. The live migration has not been applied.

## Proposed installation

Approval covers the reviewed companion artifact, one audited local reconciliation,
the project skill update, and the coordinated helper/gateway restart below.

1. Recheck idle call/media/executor state, retain the installed app and exact
   receipt/config/policy/skill backups, and stop the exact gateway and helper.
2. Refresh the private audit against current journal hashes and the retained
   pre-upgrade snapshot. Record actual stopped-helper and idle-owner evidence.
3. Run the staged companion's offline reconciliation in dry-run mode. Apply the
   same audit once only after its report matches the reviewed 41/37/4 counts.
   The migration writes only the reconciliation sidecar. If the outcome is
   uncertain, inspect that sidecar and journal before considering any retry.
4. Install the companion with the previous installed signing identity and update
   the owned skill and its ownership hash. Launch one helper and one gateway.
5. Verify original receipts, permissions, selected display, local default policy,
   zero input blockers, truthful historical counts and disabled sharing. Native
   control still requires a fresh correctly attested run and a separately
   approved physical test.

The hosted services remain on approved source `8efbacc`. This repair requires no
backend/media deployment, new pairing, new line ownership or call. It is an
internal signed artifact, not a notarized public download.

## Recovery

Preserve the original journal, reconciliation sidecar and exact audit evidence
through any rollback. Restore the retained app only after ending any later owned
call, releasing capture and reconciling pending effects. Do not restore an old
database/cursor, replay an input, or erase a sidecar to make readiness pass.
The previous companion still blocks the historical submissions; rollback does
not establish control readiness. Local Enable and fresh call approval remain
separate from installation.
